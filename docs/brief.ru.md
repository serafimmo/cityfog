Помоги мне разработать Android-приложение для личного использования. Идея — игра в стиле "туман войны" (как Fog of World), но с клеточной механикой.

## Суть приложения
Карта моего города (Казань). Пока я физически перемещаюсь по городу — пешком, на велосипеде или самокате — приложение отслеживает мою геопозицию через GPS и "открывает" территорию вокруг меня. Цель — открыть как можно больше города, в идеале дойти до 100%.

## Ключевая механика — клеточная сетка
Вместо рисования "кистью" по треку, вся территория разбита на квадратные клетки. Когда я физически захожу в клетку — она помечается как посещённая навсегда.
- Размер клетки: 10-15 метров (НЕ 5м — это меньше точности городского GPS, будет открываться рандом)
- Каждой клетке присваивается уникальный ID на основе координат (например через целочисленное деление lat/lon на размер клетки)
- Хранить нужно только Set посещённых ID клеток (а не весь GPS-трек) — это экономит память
- Процент = посещённые клетки / общее число "доступных" клеток * 100

## Определение какие клетки вообще считать "доступными"
Это главный концептуальный вопрос — без этого 100% недостижимо в принципе (водоёмы, заводы, частные территории). Два подхода на выбор, обсуди со мной плюсы/минусы перед реализацией:

**Вариант А — по дорогам.** Берём только клетки, через которые проходят дороги/тропинки/дворовые проезды из OSM (теги highway=*). Всё остальное не считается. Проще, честнее логически (ты же физически ходишь по дорогам, не сквозь стены).

**Вариант Б — по площади с фильтрацией.** Берём все клетки города, но вычитаем заведомо недоступные через OSM-теги:
- natural=water — водоёмы, исключить
- landuse=industrial — заводы, исключить
- landuse=military — военные объекты, исключить
- access=private — частные территории, исключить
- Остальное (residential, parks, etc.) — считать доступным

OSM-данные для Казани грузить один раз с Geofabrik (.osm файл), парсить локально, сохранять разметку клеток в БД при первом запуске/обновлении.

Я склоняюсь к гибриду: по умолчанию вариант А (только клетки у дорог), но дополнительно открывать клетки если GPS реально показал что я там был (даже если OSM не разметил это как дорогу — тропинки и дворы часто отсутствуют в OSM).

## Ручная отметка непроходимых клеток
OSM-разметка для Казани неполная (особенно дворы, гаражные кооперативы, новостройки, частный сектор) — это нормально и не страшно, но хочу возможность вручную корректировать:
- Отдельный "режим редактирования" в приложении (не во время катания, а дома за столом)
- Открываю карту, зумлюсь в проблемное место
- Тапаю по клетке → помечается вручную как "недоступна" (например реально там забор, гараж, частная территория)
- Такие клетки вычитаются из общего количества "доступных" при расчёте процента
- НЕ делать это частью MVP — добавить позже, после того как я погуляю с приложением хотя бы месяц и пойму реально ли это нужно. На старте можно просто считать все клетки доступными и закрывать по факту GPS-посещения, без фильтрации вообще.

## Подсчёт по районам
Казань делится на административные районы (полигоны брать из OSM). Хочу видеть процент закрытия каждого района отдельно, например:
✅ Ново-Савиновский    23%
⬜ Московский           4%
Первая цель — закрыть Ново-Савиновский на 100%, он маленький и компактный (20 км²), в отличие от Московского (39 км², большая часть — промзона и поля, бессмысленно гнаться).

## Что важно учесть технически
1. ФОНОВЫЙ GPS — главная сложность. На Android 12+ система агрессивно убивает фоновые сервисы. Нужен правильно настроенный Foreground Service, запрос исключения из оптимизации батареи, корректные permissions (ACCESS_BACKGROUND_LOCATION). У приложения Fog of World это сломано в свежих версиях — учти их грабли, не повторяй архитектуру с этой проблемой.
2. Всё работает ЛОКАЛЬНО — никакого сервера, аккаунтов, облака. Данные в локальной БД на телефоне.
3. Карта оффлайн или с кэшем тайлов, чтобы не сжигать трафик при катании.

## Стек (предлагаю, можешь скорректировать)
- Kotlin + Android Studio
- Mapbox SDK или MapLibre (бесплатно для личного использования)
- Room — локальная БД для хранения посещённых клеток и ручных пометок
- Foreground Service для GPS-трекинга

## Дополнительные фичи (НЕ для MVP, на будущее, по приоритету)
1. Ручная отметка непроходимых клеток (см. выше, после месяца использования)
2. Тепловая карта по частоте посещения (не просто открыто/закрыто, а градиент яркости)
3. Статистика: км за выезд, новые клетки за сегодня, графики прогресса
4. Достижения по кварталам/районам
5. Экспорт трека в GPX
